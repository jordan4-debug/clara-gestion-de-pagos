## Reglas de interpretación

1. HU-05 dice que se registran pagos externos sin débitos reales; RF-11 a RF-14 piden además una simulación bancaria. Se conservan ambos recorridos, separados: **Pago simulado** genera un voucher de prueba y **Registrar pago realizado fuera de Clara** archiva una constancia declarada. Ninguno mueve dinero real.
2. La instrucción actual RF-16/RNF-12 reserva la operación de pagos al asistente. Sustituye el pago excepcional del propietario descrito en la reunión anterior. El servidor también lo rechaza.
3. El saldo inicial es un presupuesto de simulación para un mes, no una recarga. El total pagado se calcula por fecha de registro de la operación en Lima, incluso si corresponde a una deuda de otro mes. Disponible = inicial − total registrado en el mes. La proyección resta las obligaciones pendientes del mes seleccionado. No se inventa saldo para los periodos sin configurar.
4. El registro de un pago externo ya ocurrido cuenta como egreso en el presupuesto mensual y puede revelar un déficit. La ejecución de una simulación siempre exige fondos suficientes. Registrar un hecho externo no equivale a ejecutar una transferencia.
5. SAT se denomina **SATT** para el caso de Trujillo. El simulador usa cuentas `DEMO-…`; no liquida tributos ni emite documentos tributarios oficiales.
6. Las cuotas del cronograma pueden existir antes de recibir su recibo mensual. Se exige adjuntarlo con número **antes de abonarlas**, tal como indica HU-04. Los documentos y pagos anteriores se conservan.
